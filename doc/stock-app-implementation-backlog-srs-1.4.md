# Implementation backlog จาก SRS ฉบับ 1.4

**วันที่:** 13 พฤศจิกายน 2026  
**เป้าหมาย:** แอปมือถือบันทึกหุ้น/ETF หลายบัญชี คำนวณกำไรและขาดทุนจากการขายด้วย FIFO หรือ moving weighted average ตรวจย้อนถึงเอกสาร และบันทึกวันเงินเข้าจริง  
**วิธีใช้:** แต่ละหัวข้อเป็นฟีเจอร์ใหญ่ (Epic) รายการ `[ ]` เป็นงานที่ต้องทำ; “เสร็จเมื่อ” คือเกณฑ์ตรวจรับระดับฟีเจอร์ ตัวเลข ID ใช้อ้างอิงในบอร์ดงาน ไม่ใช่ลำดับที่ทุกทีมต้องทำต่อกันทั้งหมด

## E00 — ข้อกำหนดที่ต้องปิดและชุดข้อมูลทดสอบ

- [ ] ระบุตลาด/ประเภทหุ้นและ ETF รวมถึงโบรกเกอร์กับรูปแบบเอกสารที่จะรองรับในรุ่นแรก
- [ ] รับเอกสารตัวอย่างที่ได้รับอนุญาต: ซื้อ ขาย รายการเงินเข้า split/transfer/distribution; ลบข้อมูลส่วนตัวสำหรับชุดทดสอบ
- [ ] ตกลงเอกสารที่เพียงพอสำหรับสถานะ “มีหลักฐาน”, เกณฑ์เทียบยอด/การปัดเศษ, และความหมายของ “กระทบยอดครบทั้งบัญชี”
- [ ] กำหนดขอบเขต corporate actions ที่คำนวณได้กับเหตุการณ์ที่ต้องขึ้น UNRESOLVED
- [ ] ตัดสินวิธีสมัคร/กู้บัญชี, แพลตฟอร์มมือถือ, ผู้ให้บริการ AI, ขนาดไฟล์, อายุเก็บ/ลบข้อมูล, นโยบายสำรองข้อมูล และค่าตั้งต้นของตัวกรอง
- [ ] จัดทำ golden cases สำหรับ FIFO/เฉลี่ย, หลายบัญชี, เศษหุ้น, fee 0/unknown, ขาดทุน, ขายหลายล็อต, แก้ย้อนหลัง, split/transfer และเงินเข้าคนละปี

**เสร็จเมื่อ:** decision log ระบุคำตอบ/เจ้าของ/เวอร์ชัน และ golden cases มีผลที่ตรวจมือได้; งานที่ยังไม่ตกลงถูกทำเครื่องหมาย blocked เฉพาะส่วน ไม่เดากฎในโค้ด  
**อ้างอิง:** Release gates, BR-01–05, TC-01–16

- [ ] สร้างคอมโพเนนต์พื้นฐาน: การ์ดยอด, badge สถานะ, ตัวกรอง, ฟอร์มตัวเลข/วันเวลา, การ์ดซ้อน, กราฟพร้อมรายการตัวเลข, bottom sheet, empty/error/loading
- [ ] เตรียมข้อความไทยและโครง English localization; รูปแบบจำนวน สกุลเงิน วันที่ และค่าติดลบ

**เสร็จเมื่อ:** หน้าจอ S01–S10 มีโครงและสถานะสำคัญ กดนำทางได้; ตัวเลขและกราฟอ่านได้ด้วยข้อความ/เครื่องมือช่วยการเข้าถึง  
**อ้างอิง:** NAV-01, S01–S10, UI specification, NFR-05

## E02 — บัญชีผู้ใช้ สิทธิ์ และซิงก์หลายเครื่อง

- [ ] ทำสมัคร/เข้าสู่ระบบ/กู้บัญชีตามวิธีที่เลือก และผูก owner_id กับทุกข้อมูล/ไฟล์
- [ ] ออกแบบ API ที่ตรวจเจ้าของ server side, idempotency key, entity revision และข้อความเมื่อข้อมูลชนกัน
- [ ] ทำการโหลด/รีเฟรชข้อมูลจากสองเครื่อง; หากแก้รายการเดียวกันพร้อมกันให้ตรวจ conflict ไม่เขียนทับเงียบ
- [ ] เก็บ cache สำหรับอ่านข้อมูลล่าสุดบนเครื่อง; กำหนดพฤติกรรมชัดเมื่อ offline และห้ามแสดงยอดเก่าว่าเป็นยอดที่เพิ่งคำนวณ
- [ ] ทดสอบการเข้าถึงข้อมูล/ไฟล์ข้ามผู้ใช้, session หมดอายุ และการกู้ข้อมูลหลังเปลี่ยนเครื่อง

**เสร็จเมื่อ:** คนเดียวกันเห็น revision ล่าสุดบนสองเครื่อง; คนอื่นอ่าน/แก้รายการหรือไฟล์ไม่ได้; retry ไม่สร้างรายการซ้ำ  
**อ้างอิง:** DECISION-AUTH, Interface, NFR-01/04, TC-06

## E03 — บัญชีโบรกเกอร์ สินทรัพย์ และยอดตั้งต้น

- [ ] เพิ่ม/แก้/เก็บถาวรเชิงสถานะบัญชีโบรกเกอร์ด้วยชื่อโบรกเกอร์ ชื่อเรียก สกุลเงินหลัก และฟิลด์เสริม
- [ ] รองรับหลายบัญชีของโบรกเกอร์เดียวกัน และระบุหุ้นด้วยตลาด/รหัสเพื่อไม่รวม symbol คนละสินทรัพย์
- [ ] เพิ่มรายการซื้อย้อนหลังหรือ opening position ที่มีจำนวนแต่ต้นทุนยังไม่ทราบ
- [ ] แสดงว่าข้อมูล/statement ครอบคลุมช่วงไหน แยกจากสถานะหลักฐานของรายการหนึ่ง
- [ ] ป้องกันการขายในบัญชี A จากการดึงหุ้นหรือต้นทุนบัญชี B; จัดการผลเมื่อ archive บัญชีที่มีข้อมูล

**เสร็จเมื่อ:** เพิ่มบัญชีสองบัญชีที่ถือหุ้นตัวเดียวกันได้; หุ้นตั้งต้นที่ไม่มีต้นทุนแสดงจำนวนแต่ไม่สร้างกำไรที่มีหลักฐาน  
**อ้างอิง:** FR-01, BR-04, TC-02

## E04 — บันทึกซื้อขายด้วยมือและหน้ารายการ

- [ ] ทำฟอร์มซื้อ/ขายแบบขั้นสั้น: บัญชี สินทรัพย์ วันเวลา จำนวน ราคา สกุลเงิน ยอดรวม fee/fee=0/unknown และเอกสาร
- [ ] เก็บ draft/needs review/confirmed/evidence status แยกกัน; ตรวจจำนวนที่ขายกับหุ้นที่มีและฟิลด์จำเป็น
- [ ] ตรวจรายการซ้ำด้วย external reference และ fingerprint; ให้ผู้ใช้เลือกใช้รายการเดิมหรือสร้างใหม่
- [ ] ทำแท็บรายการ “ทั้งหมด/รอตรวจ/ฉบับร่าง” พร้อมค้นหา กรอง รายละเอียด และงานค้าง
- [ ] แก้/ยกเลิกรายการพร้อม revision, audit trail และผลกระทบต่อรายการที่เกิดภายหลัง

**เสร็จเมื่อ:** เพิ่มทั้งไม้กำไรและขาดทุนได้; fee unknown/ต้นทุนขาดไม่หลุดเข้ายอดหลัก; แก้ย้อนหลังแล้วไม่ทิ้งยอดคำนวณครึ่งหนึ่ง  
**อ้างอิง:** FR-02, BR-04/05, S05/06, TC-06/07/11

## E05 — Calculation engine: FIFO และ moving weighted average

- [ ] สร้างการคำนวณ decimal และลำดับเหตุการณ์ที่ตัดสินได้แม้ timestamp เท่ากัน
- [ ] ทำ FIFO: ล็อตซื้อ ค่าธรรมเนียมซื้อที่จัดสรร การขายบางส่วน และ LotAllocation
- [ ] ทำ moving weighted average: ต้นทุนรวม/จำนวนก่อนขาย ราคาเฉลี่ย การตัดต้นทุน และ CostPoolSnapshot
- [ ] คำนวณ gross proceeds, net proceeds, matched cost และ realized P/L ทั้งค่าบวก/ลบ; เก็บ method/version และ data_revision
- [ ] replay แบบ atomic เมื่อเพิ่ม/แก้/ยกเลิกย้อนหลังหรือเปลี่ยนวิธี; ปฏิเสธผลที่ทำให้ขายเกินจำนวน และแสดงรายการที่กระทบ
- [ ] ทดสอบ golden cases ทั้งสองวิธี เศษหุ้น fee 0/unknown การปัดเศษ หลายบัญชี หลายล็อต และผลรวมต้นทุนคงเหลือ

**เสร็จเมื่อ:** ผลตัวอย่างซื้อ 100/200 ขาย 250 คือ FIFO กำไร 150 ต้นทุนเหลือ 200 และวิธีเฉลี่ยกำไร 100 ต้นทุนเหลือ 150; replay ซ้ำจากข้อมูล/เวอร์ชันเดียวกันได้ผลเท่าเดิม  
**อ้างอิง:** BR-01–05, FR-04, TC-01/02/07/12/13/15

## E06 — เลือกวิธีต้นทุนและ simulator

- [ ] ออกแบบหน้าช่วยเลือก FIFO/เฉลี่ยโดยใช้สถานการณ์เดียวกัน พร้อมภาพผลขาย ต้นทุนคงเหลือ และคำอธิบายสั้น
- [ ] เมื่อมีประวัติจริง ให้รันทั้งสองวิธีในโหมด preview และแสดงผลต่างรายไม้/ยอดรวม/รายการที่ยังคำนวณไม่ได้
- [ ] แยกค่า preview ออกจากวิธีที่ใช้กับยอดหลัก; เปลี่ยนวิธีต่อบัญชีได้หลังผู้ใช้เห็นผลกระทบและยืนยัน
- [ ] หลังเปลี่ยน ทำ replay และอัปเดตกราฟ/รายการตาม revision เดียวกัน; รายงาน snapshot เก่ายังคงวิธีและผลเดิม
- [ ] ทดสอบว่าเข้า/ออก simulator หรือสลับวิธีตัวอย่างไม่เปลี่ยนข้อมูลจริง

**เสร็จเมื่อ:** ผู้ใช้เห็นเหตุผลของตัวเลขที่ต่างกันก่อนเลือก และไม่มีการเปลี่ยนยอดจริงโดยไม่ยืนยัน  
**อ้างอิง:** BR-03, FR-04, S10, TC-15

## E07 — Corporate actions และเหตุการณ์เปลี่ยนต้นทุน

- [ ] ออกแบบ event type, วันมีผล, สินทรัพย์/บัญชีต้นทางปลายทาง, จำนวน ต้นทุน เงินสด เอกสาร และสถานะ supported/requires input/unresolved
- [ ] ทำกฎ split/reverse split และเศษหุ้น/เงินสดแทนเศษหุ้นตามขอบเขตที่ตกลง
- [ ] ทำการโอนหุ้นโดยรักษาจำนวนและต้นทุน; กรณีต้นทาง/ปลายทางต่างวิธีต้องมีกฎที่ตรวจได้หรือค้างตรวจ
- [ ] บันทึก ETF distribution, dividend, reinvestment และเหตุการณ์ที่เปลี่ยนสินทรัพย์/ต้นทุนตามชนิดที่เอกสารรองรับ
- [ ] replay FIFO และเฉลี่ยหลังเหตุการณ์; กั้นกำไรจากการขายที่พึ่งพา unresolved event
- [ ] ทดสอบจำนวน/ต้นทุนก่อนและหลังเหตุการณ์ รวมทั้งการแก้เอกสารหรือกฎย้อนหลัง

**เสร็จเมื่อ:** เหตุการณ์ที่รองรับคงจำนวนและต้นทุนถูกต้อง; เหตุการณ์ที่ยังคำนวณไม่ได้ถูกบันทึกและไม่สร้างกำไรที่ติดป้ายว่ามีหลักฐาน  
**อ้างอิง:** BR-05, DECISION-CORPORATE, S04

## E08 — คลังหลักฐานและการตรวจข้อมูลต้นทาง

- [ ] อัปโหลดรูป/PDF เข้าพื้นที่ private ตรวจ MIME/ขนาด/หน้า/hash และจำกัดสิทธิ์การเปิดไฟล์
- [ ] เชื่อมเอกสารซื้อ/ขายกับฟิลด์ต้นทางและหน้า/ตำแหน่งในไฟล์; แยกค่าที่อ่าน ค่าแก้ และค่าคำนวณ
- [ ] ทำ UI เทียบค่า “เอกสาร / นำเข้า / จะบันทึก” รายฟิลด์ พร้อมสถานะไม่พบ/ไม่ตรง/ตรวจแล้ว
- [ ] กำหนดสถานะ evidence แยกจาก confirmation และสถานะ reconcile ของบัญชี; รายการไม่มีหลักฐานอยู่ใน preview/งานรอตรวจ
- [ ] เมื่อไฟล์หาย/ลบ/เปิดไม่ได้ ประเมินรายการและยอดที่พึ่งพาใหม่ พร้อมเหตุผลและทางแนบไฟล์ทดแทน
- [ ] ทดสอบสิทธิ์ไฟล์, ลิงก์หมดอายุ และผลต่อรายงาน/กราฟเมื่อหลักฐานเปลี่ยน

**เสร็จเมื่อ:** แตะค่าต้นทางแล้วเปิดเอกสารได้; ค่าต้นทุนจัดสรรมีป้าย “คำนวณจากรายการ”; ลิงก์เสียไม่ถูกนับเป็นหลักฐานที่ตรวจได้  
**อ้างอิง:** BR-01/04, FR-02/04, CalculationEvidenceLink, TC-11–14

## E09 — AI อ่านเอกสารและตรวจหลายรายการ

- [ ] ทำ notice/ตัวเลือกครั้งแรกสำหรับใช้ AI และทางกรอกมือ; แยกสิทธิ์ใช้ไฟล์พัฒนาโมเดลเป็น opt-in ที่ปิดโดยปริยาย
- [ ] ทำบริการ import แบบ async: ตรวจไฟล์ สแกน/อ่าน แยก candidates, raw/normalized/confidence และหน้า/บริเวณต้นทาง
- [ ] ออกแบบการ์ดซ้อนพร้อมจำนวน n/N, ปุ่มยืนยัน/แก้/ข้าม, flag จุดไม่มั่นใจ และ resume หลังออกจากหน้า
- [ ] AI ส่งเฉพาะ draft; ผู้ใช้เทียบค่าบนไฟล์/ค่าที่ AI อ่าน/ค่าที่จะบันทึกและแก้ก่อนยืนยัน
- [ ] ป้องกันอัปโหลดหรือยืนยันซ้ำด้วย hash, source_document_id, external ref และ idempotency key
- [ ] ทดสอบเอกสารโบรกเกอร์ที่ได้รับอนุญาตด้วยชุด holdout วัดจำนวนรายการที่พบและความถูกต้องรายฟิลด์ก่อนประกาศรองรับ

**เสร็จเมื่อ:** ไฟล์ 5 รายการยืนยัน 3/ข้าม 2 แล้วยังเหลือรอตรวจ 2; AI อ่าน 2.5 เป็น 25 แล้วผู้ใช้แก้ได้โดยค่า 25 ไม่เข้ายอด; ปิด AI แล้วไม่ส่งไฟล์ใหม่ไปประมวลผล  
**อ้างอิง:** FR-03, DECISION-FILE-LIMIT/PRIVACY, TC-04–06/16

## E10 — รายการเงิน วันรับจริง การแลกและการโอน

- [ ] สร้างบัญชีเงินและ MoneyEvent สำหรับ sale proceeds, dividend, interest, deposit, withdrawal, FX, transfer และ Thailand remittance
- [ ] แยกวันที่ทำรายการ/ชำระราคา/เงินเข้าจริง; ถ้าไม่รู้ cash_credited_at ให้ PENDING_RECEIPT ไม่เดาวัน
- [ ] เชื่อมเงินขายสุทธิกับรายการขายและหลักฐานเงินเข้า; ป้องกันการสร้างรายรับซ้ำจากโอนหรือแลกเงิน
- [ ] บันทึกจำนวนและสกุลเงินเข้า/ออก อัตราจริง fee และหลักฐานของ FX; แสดง USD/THB แยกถ้าไม่มีฐานแปลง
- [ ] ทำ log วัน/ปีและตัวกรองตามชนิดเงิน; remittance เชื่อมต้นทางหลายส่วนหรือ UNKNOWN_SOURCE
- [ ] ระบุว่า cash flow ที่ไม่ได้ reconcile ไม่ใช่ “ยอดเงินคงเหลือจริง”

**เสร็จเมื่อ:** ขาย 30 ธ.ค. เงินเข้า 2 ม.ค. แสดงกำไรตามปีขายและ log ตามปีรับ; โอนต่อไม่เพิ่มรายรับหรือกำไรหุ้น  
**อ้างอิง:** FR-05, BR-05, S08, TC-08/10

## E11 — พอร์ต ภาพรวม และกราฟที่มาของกำไร

- [ ] ทำพอร์ตแยกบัญชี/สินทรัพย์: ซื้อสะสม ขายแล้ว คงเหลือ ล็อต FIFO หรือกองต้นทุนเฉลี่ย และประวัติ
- [ ] ทำยอดหลักเฉพาะรายการขายที่ยืนยัน/คำนวณ/หลักฐานครบ พร้อมตัวกรองบัญชี ช่วงเวลา สกุลเงิน จำนวนรวมและจำนวนกันออก
- [ ] ทำกราฟกำไร/ขาดทุนแยกหุ้นและกราฟเวลา; แตะไปยังรายการขายแต่ละไม้
- [ ] ทำ waterfall ต่อการขาย: ยอดขายรวม − fee ขาย = เงินขายสุทธิ; − ต้นทุน = กำไร/ขาดทุน; แตะดูที่มาของต้นทุนและเอกสาร
- [ ] คงตัวกรองเมื่อเจาะลึก/ย้อนกลับ; กราฟและยอดใช้ data_revision เดียวกัน ไม่รวมต่างสกุลแบบเงียบ
- [ ] ทำ empty/pending/unresolved/loss states พร้อมข้อมูลตัวเลขที่ screen reader อ่านได้

**เสร็จเมื่อ:** +40 และ −15 ได้ยอด +25 ทุกระดับ; รายการรอตรวจแสดงจำนวนแต่ไม่รวม; เปิดไม้ขาดทุนได้ลึกเท่าไม้กำไร  
**อ้างอิง:** BR-01/02, FR-04, S02–04, TC-03/10/12–14

## E12 — รายงาน PDF/CSV และประวัติฉบับ

- [ ] ทำ preview ตัวกรองและรายการที่รวม/กันออกก่อนสร้างรายงาน
- [ ] สร้าง PDF/CSV จาก immutable snapshot เดียวกัน มีขายกำไร/ขาดทุน วิธีต้นทุน/เวอร์ชัน matched cost หรือกองต้นทุน เงินรับรายวัน/ปี และหลักฐานอ้างอิง
- [ ] ใส่ report_id, generated_at, filters, data_revision, status summary; แก้ธุรกรรมแล้วสร้างฉบับใหม่ไม่ overwrite
- [ ] แสดงข้อจำกัดข้อมูล/หลักฐาน/วันรับที่ยังไม่ทราบ และใช้ชื่อ “สรุปข้อมูลการลงทุนและเงินรับ” ไม่แสดงภาษีที่ต้องจ่าย
- [ ] ตรวจตัวเลข PDF/CSV กับยอดบนหน้าจอ ณ snapshot เดียวกัน และการเปิดไฟล์เก่าหลังแก้ข้อมูล

**เสร็จเมื่อ:** รายงานเก่าคงตัวเลข/วิธีเดิม; รายงานใหม่สะท้อนการแก้ไขพร้อม revision; ผู้ใช้ส่งออกข้อมูลของตนได้  
**อ้างอิง:** FR-06, ReportSnapshot, TC-09/11

## E13 — ตั้งค่า ความเป็นส่วนตัว และวงจรชีวิตข้อมูล

- [ ] ทำตั้งค่าบัญชีโบรกเกอร์/บัญชีเงิน วิธีต้นทุน และสวิตช์ AI พร้อมประวัติการเปลี่ยน choice/notice version
- [ ] ออกแบบอายุเก็บไฟล์ต้นทาง ไฟล์ import ชั่วคราว รายงาน และ backup แยกกัน; แสดงผลต่อสถานะหลักฐานก่อนลบ
- [ ] ทำส่งออกข้อมูลผู้ใช้ ลบไฟล์/บัญชีตามนโยบายที่ตกลง และวิธีกู้คืนเมื่ออยู่ในช่วงที่ประกาศไว้
- [ ] เก็บ audit events ของการยืนยัน แก้ ลบ เปลี่ยนวิธีต้นทุน AI choice และ export โดยไม่ใส่ภาพ/เลขบัญชีเต็มใน analytics
- [ ] จัดการสิทธิ์ AI: ปิดแล้วไม่ส่งไฟล์ใหม่; ไม่สื่อว่าปิดแล้วไฟล์ที่เคยประมวลผลถูกลบทันที

**เสร็จเมื่อ:** ตัวเลือกมีผลจริงกับไฟล์ใหม่และการลบไม่ทิ้งป้าย “มีหลักฐาน” ของรายการที่ไฟล์หาย; นโยบายเปิดเผยต่อผู้ใช้ก่อนใช้งานจริง  
**อ้างอิง:** FR-03, S10, NFR-02/07/08, TC-05/14

## E14 — ทดสอบระบบ ปฏิบัติการ และเปิดใช้งาน

- [ ] รัน golden cases ที่ E00 ทั้งระดับ engine/API/UI และตรวจ invariants จำนวนหุ้น ต้นทุน และผลรวมกราฟ
- [ ] ทดสอบ auth/owner isolation, private files, duplicate retries, conflict สองเครื่อง และ replay/export atomic
- [ ] ทดสอบ backup/restore ด้วยข้อมูลตัวอย่างที่มีไฟล์และรายงาน; กำหนดเป้าหมาย performance จากอุปกรณ์และขนาดประวัติจริง
- [ ] ทำ observability: error code, duration, parser version, field correction, calculation version โดยไม่ log ข้อมูลอ่อนไหว
- [ ] Pilot กับเอกสารจริงที่ได้รับอนุญาต; เทียบยอด/รายการกับ statement และระบุความครอบคลุมตามโบรกเกอร์/รูปแบบ
- [ ] ตรวจ release gates ทั้งหมดก่อนเปิด AI กับไฟล์จริงและก่อนติดป้ายยอดว่า “มีหลักฐาน”

**เสร็จเมื่อ:** ไม่มีกรณี known ที่ยอดกำไรผิดเงียบ ข้อมูลผู้ใช้อื่นเข้าถึงไม่ได้ กู้ข้อมูลได้ตามนโยบาย และรูปแบบเอกสารที่ประกาศรองรับผ่านเกณฑ์ที่กำหนด  
**อ้างอิง:** NFR-01–08, TC-01–16, Release gates
